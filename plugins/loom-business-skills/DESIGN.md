# 外部 agent 业务经验插件设计

## 目标与边界

实现 issue #1 的「探索 → 沉淀 → 线上校验 → 复用/刷新」闭环。代码位于独立的 `plugins/loom-business-skills/`，可单独打包、安装和删除。Loom 服务端、通用 `personal-computing-space` skill、SDK、协议及既有冷启动验收均不修改。插件只依赖已发布的 `loom-orchestration` 公共客户端，生产部署无需变化。

采用 Agent Plugins 根目录 `plugin.json` 与一个入口 skill；本地 Python CLI 提供确定性的缓存与核验操作。格式依据 [官方插件打包规范](https://developers.openai.com/plugins/build/plugins)，本地执行需求通过 `extensions.com.openai.requires_local_executor` 声明。无需 MCP 常驻服务、hook 或中心技能市场。

## 上下文预算

插件只注册 **一个**入口 skill。业务经验虽然可导出为独立 `SKILL.md`，但存放于 agent 私有缓存的 `experiences/` 下，不能复制或链接进自动发现的 skills 目录。

- `find` 只查询摘要索引，默认返回 3 个候选，上限 5 个，不输出正文、契约或历史证据。
- 选定一条经验后，`prepare` 在线核验，成功时才返回该条经验的精简步骤。较大的 schema、文档和业务结果不自动输出。
- 每条经验至多 8 个步骤；每步分别记录简短方法、验收条件、失败处理。详细契约通过独立的按需读取命令取得一个绑定的一个字段。
- 学习、检查、执行默认只输出状态摘要；原始业务结果写入调用者指定的私有结果文件，永不进入经验缓存。
- 缓存增加到上千条时，常驻入口数量、候选数量和单次正文大小仍保持有界。针对这些行为写独立测试。

## 数据与权威

缓存默认位于 `~/.local/share/loom-business-skills/`，可显式指定。SQLite 是记录和摘要索引的唯一数据源；`experiences/<id>/SKILL.md` 是可删除、可重新生成的阅读视图。缓存目录 0700，文件 0600。缓存不随插件 ZIP 分发。

经验包括：业务目标、检索词、参数化步骤、验收/失败处理、Observer 与 workspace 来源、发现时间、最近校验/执行/验收时间，以及命名激活、包、action、descriptor、schema、文档和依赖的公开引用。绑定必须由调用者从公开发现结果中明确选择；同一目标多实例时不按顺序选择。跨环境使用需要完整显式重绑定，不能改写 URI 前缀。

线上包 digest 和不可变引用原样保存。插件自身的比较摘要明确命名为 `local_fingerprint`，不冒充服务端 digest。只缓存契约元数据、schema 和包文档引用；不复制浏览器数据、凭据、私有配置、业务请求参数或业务响应。自由文本由 agent 参数化整理；已知凭据模式拒绝写入，但检测不是任意敏感信息识别器，共享前仍需人工检查。

验证等级为 `documented`、`executed`、`verified`。从公开契约学习只得到 documented；真实调用完成只得到 executed；agent 读取新结果并检查所记录验收条件后，才针对该次执行标记 verified。失败不会沉淀成「能力永久不存在」。

## 公共接口核验

`learn` 接受 agent 整理的目标与步骤，通过公共 DESCRIBE 和 read/how-to-use 解析明确选择的命名激活及其业务 action，记录契约、依赖和来源。插件不生成业务计划，不推测业务关系。

每次 `prepare` 或 `run` 都重新 DESCRIBE 所有绑定、包及声明的依赖，强制绕过 SDK description 缓存。核对目标身份、命名实例、revision、action/interaction、权限声明、descriptor/schema 引用、包 digest 和声明的依赖关系。依赖递归去重并检测部分不可用，包含调用者明确补充的依赖。动态状态和认证每次重新检查；不可变契约正文仅在学习/刷新时读取。

返回状态：

- `ready`：本次线上核验通过；不代表缓存授予用户权限，也不保证检查后的状态不会变化。
- `stale`：契约、身份、配置 revision 或依赖关系变化。明确指出受影响绑定，禁止执行旧步骤。
- `blocked`：资源缺失、认证/权限/可用性问题，或未明确选择实例。下次检查重新获取状态。
- `offline`：无法读取线上事实。只允许显式读取带 historical_only 标记的历史经验。
- `needs_rebind`：Observer/workspace 不匹配，尚未访问旧资源引用。

`refresh` 重新读取原绑定契约，保留未变步骤的证据，改变的步骤退回 documented。重新探索发现替代实例后，使用完整显式映射 `rebind` 创建新经验，所有验证证据重置。没有 TTL 免检或静默自动改绑。

## 使用与更新

入口 skill 先检索摘要，匹配时 prepare，一次只加载一条经验。没有匹配或校验失效时，仍使用既有通用发现流程；在真实任务结束后通过 learn/refresh 整理经验。在线暂不可达时可提供标注为历史的参考，但不执行旧流程。

首版 `run` 一次执行明确选定的 JSON task/request-reply 步骤，复用现有 SDK `execute_action`，先核验整个多包流程。用户的副作用授权、预算、幂等和清理约束仍由当前任务决定，插件不批量自动执行所有步骤。业务参数仅存在于本次调用和指定的结果文件；缓存只保留执行标识、状态、公开结果/Run 引用和时间。流式调用继续由现有 SDK 执行，不扩大此助手的执行范围。

## 验收

1. 独立打包后在无 Loom 服务端源码的环境运行；所有变更限定在插件目录。
2. 两条业务经验可独立检索、准备、执行、验收并跨进程复用，删除后回到冷启动。
3. 覆盖契约/权限/实例/revision 漂移、缺失资源、认证失效、离线、跨 workspace、候选歧义、多包依赖部分失效。
4. 缓存和输出中不含测试植入的凭据/原始业务数据；上下文大小与注册 skill 数量不随经验数量增长。
5. 分开记录冷启动与复用的发现调用数、耗时、返回文本量和成功率；token 指标仅在有真实模型用量时报告，不用字符数冒充 token。
6. 在现有生产公开接口上选取两个只读业务场景实测，不修改生产资源或核心系统。隔离客户端复用与独立模型会话验收分别报告，不能混为同一结果。
